相较 [V2 基线](BASELINE.md)，R1 已有可辨识的港口、资源罐、太阳翼节点与环形目标站，细航道表达了世界连接；实验室轻导航、深色背景和底部任务卡形成统一环境。四个首屏都能看到“开始补给任务”，无需先填表。0/3、能耗和时钟与未开始状态一致。这些是已经出现在真实页面中的改进。

仍需修改的具体问题：

1. **手机主构图不完整。** 390 与 360 的起点港口被左边界切掉，目标环被右边界和镜头工具条遮挡。标题与资源节点/航道叠在同一区域；用户无法从总览辨认完整任务路径。应采用手机独立相机距离、目标和构图，给标题留出天空区；不能仅缩放桌面 Canvas。
2. **宽屏标题意外断行。** 1920 首屏显示“让智能，/改变下一/步。”，1440 是预期两行。字号放大时标题容器宽度没有同步，导致“步。”成为孤行。应让第二句保持完整且不压住主体。
3. **材质仍有积木感。** 近景中的大白平板、机头和环站白色模块高光接近纯白，表面缺少粗糙度、接缝、局部金属与暗部层次。较大的平直几何体与重复白色罐体，比轮廓光更显眼。需要在受控面数下深化形体和材质，不只是增加发光。
4. **星球纹理抢眼。** 当前纹理呈高对比迷彩图案，体量贴近顶部并强压标题区；明暗交界虽可辨认，但不像远景环境。建议降低纹理对比、增强薄大气边缘和柔和明暗交界，配合相机调整。
5. **手机可点性需另测。** 图中“查看世界对象”仅表现为细小箭头，任务设置为小方图标。开始按钮已经充足，但不能因此假设所有关键操作符合 44px 触控目标。独立 E2E 将测实际元素矩形，继续核对键盘等效入口与抽屉关闭。

上述第一、二项分别把复核范围定位到手机摄影机和宽屏标题布局；第三、四项需要再次看真实截图判断，不能通过代码审阅宣布修好。集成负责人已接收 R1 反馈并安排修改。R1 的页面错误为 0，四个文档宽度均等于视口宽度；它们不改变“视觉未通过”的结论。

下一轮应保留 R1 文件，用新的 R2 文件记录相同四个视口、总览与近景，补正在执行、关闭航道后重规划和手机操作截图；继续核对真实录屏与控件命中范围。最终 60–120 秒操作影片、生产构建、性能和线上验收尚未由本轮短截图采集覆盖。
