## 路径与双载体调度

`graph.ts` 使用小图 Dijkstra。时间策略依次比较总 ticks、总能量；能量策略反向比较。相同代价再按航道 ID 稳定排序。时间权重为正整数，能量非负；关闭航道、非法方向和非法权重均不得进入路径。

资源选择比较合法取货路线与交付路线的组合代价，并检查容量、未预留库存及预计能量。如果首选路线超过剩余能量，尝试节能路线；实际进入每条航道前再次检查能量和世界版本。调度属于**按优先级的贪心预约策略**，不保证全局最优多载体解，也不保证每次世界修改后都能完成任务。

每次 `step()` 前进一个仿真 tick，每个载体最多执行一个离散动作。优先级数字较大的载体先执行，相同优先级按 ID 排序。进入航道时预约该边和下一安全节点；当前停泊及所有入站载体共同占用目标节点泊位，防止对向边冲突与节点超订。等待超过 16 次后，第 17 次产生明确 `WAIT_LIMIT`，停止运行。测试覆盖永久占用目标泊位的失败；不会为取得成功率而传送载体或释放已交付载体的真实位置。

## 提交、安全停止与变更

- 预留只增加预留数，不扣实体库存；装载同时扣库存及预留，增加载荷。
- 进入航道只扣一次能量；到站必须逐 tick 完成该航段，不能直接修改位置。
- 交付将载荷计入目标任务和载体的已交付数。所有站点库存 + 所有载荷 + 已交付数始终等于初始库存。
- 预留、装载、进入航道、到站、交付及取消都有本轮唯一动作 ID。重复终态操作不会再次扣货或交付。
- 关闭或重开航道、改变策略、优先级和未交付任务的目标均递增 `worldVersion`，清除旧未来路线。已经进入的航道即使关闭，仍执行到下一安全节点再规划。
- 交付开始后拒绝更换目标，避免把原目标的交付算给另一站点。交付前变更目标同步更新任务标题。
- 暂停保留当前 tick、在途进度和预留。取消释放尚未装载的预留，保留已经装载、耗能、在途位置和已交付事实；此轮不能再恢复执行。
- 失败后的 `retry()` 使用当前世界与已提交事实，只重试剩余工作，并重新检查库存。重置才创建新 run 并恢复固定场景。

另有限制：最多 64 次重规划、768 个动作、512 条完整事件、240 ticks，并受任务自身 180 ticks 截止约束。运行时累计计算完整事件的实际字节和 JSON 结构节点预算，每次接受事件都预留失败说明及最终取消的记录空间。候选动作若超出预算，只回退该次尚未发布的候选状态并停止，此前所有已提交动作保留；不是删除旧事件腾空间。超限需要重置。

## 同源比较与只读回放

`compareOrbit(snapshot, forkSeq)` 从同一克隆快照创建时间、能量两个独立分支，保留库存、预留、载荷、剩余能量、位置、在途进度、等待预算及故障时间表；重新规划未来路径。结果包含 `parentRunId`、`forkSeq`、`sourceKey`、实际额外 ticks/耗能/等待、实际航道轨迹和不变量结果。原运行没有写入。

`sourceKey` 包含影响后续运行的世界、任务、状态、动作与故障事实，忽略提示文案、工具耗时及暂停/运行展示差别。它是陈旧结果检查用的确定性摘要，不是密码学签名。正常初始场景观察到真实时间/能量取舍；故障后某些快照两策略结果相同，这是合法结果。

导出记录包含初始输入、seed、版本及每个事件的完整快照。导入限制为 8 MiB、512 事件，并限制深度、数组、字符串和字段；拒绝访问器、原型污染字段、循环、稀疏数组、非 JSON 值。除每帧不变量，还检查相邻动作、库存、能量、目标、图属性、故障时序、世界版本和物理移动历史。进入航道必须匹配当时开放、版本有效的计划，到站必须来自此前在途终点并完成 duration。单帧看似守恒但位置跳跃、改能量、移仓、缩短行程等记录仍会拒绝。

验证成功返回深冻结对象；对同一对象只验证一次，后续 seek 只克隆所选快照。`replayOrbit(recording, -1)` 为初始快照，`0` 为第一条事件；回放不创建 runtime、不派发工具、不请求网络。导入历史检查证明记录内部一致性，**不认证记录作者、外部来源或初始世界的真实性**。
