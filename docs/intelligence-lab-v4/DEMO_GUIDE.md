## 演示前准备

- 当前开发入口为 `http://127.0.0.1:5184/#/intelligence/preview-v4`。这是本机临时服务，不能作为公开体验链接。最终生产入口由实际发布记录确认。
- 使用默认“远征接力 · 勘测与维修”，种子4217。通过“世界设置 → 重置并应用场景”开始新会话；不会改写前一个会话的历史。
- 默认本地规划仿真、声音关闭。所有天体尺度、库存、舰船和任务数据为原创合成场景；不依赖公网API、订单或真实模型。
- 若启用了减弱动效，页面优先提供同状态的二维星图。三维资源异常也可使用二维继续业务操作；不把图形回退当作任务失败。

## 30秒看亮点

1. **0–8秒：**看曙光环港与六艘三类舰，点“指挥桥”或“跟随”，说明镜头只改变观察位置。随后回到“全域”。
2. **8–22秒：**运行速度选4×，点“启动远征”。打开“任务编排”，观察扫描完成以前维修和运输仍等待依赖。以实际状态为准，不用口播宣布尚未出现的完成。
3. **22–30秒：**打开“工程档案”，指出真实事件、库存/舰载/耗能账本，再用“全息星图”说明二维和三维来自同一会话。

30秒是讲述预算，不是任务完成时限。低性能设备或被用户干预的世界可能需要更久；保留等待、受阻或失败状态，解释其依据。

## 可现场触发的失败与恢复

### 旧提案失效

1. 在暂停世界生成一个受控提案，记住任务数；不批准。
2. 点“单步”，让真实世界变化。
3. 点击“批准一个任务”：应收到 `STALE_APPROVAL`，任务数不增加。
4. 重新生成并批准新提案，才增加一个待执行任务；批准不是交付。

该流程已在开发Chrome实际检查，导出记录确认只有一次被接受的 `add-mission`。它是主动触发的回归场景，不是生产事故。

### 禁行与维修的边界

导览在扫描实际完成后关闭 `forge-relay`。维修完成后，该航道仍保持用户关闭；舰船通过其他合法路径完成任务。可在对象面板检查许可状态与损坏状态分别显示。解除禁行必须是显式的开放命令，不能靠维修动画绕过权限。

“全部封闭 → 原因明确 → 开放 → 显式重试”、断连/重连、资源耗尽等操作已实现并有领域测试入口；其最终生产浏览器结果由统一报告确认，不在本页提前宣称全部通过。

## 五个源码追问

1. **为什么六艘舰不会各自写坏世界？** 从[运行时](../../packages/intelligence/src/dominion/runtime.ts)的 `createDominionRuntime`、`apply`、`tick`、`schedule` 看起。命令验证后才产生动作与事件；[场景](../../apps/portfolio/src/components/dominion/DominionScene.vue)的 `updateFacts` 只投影快照，帧率不能改变燃料和交付。
2. **资源预留与交付怎么避免重复计算？** 看 `releaseReservation`、`act`、`finishStep` 和[不变量](../../packages/intelligence/src/dominion/invariants.ts)的 `assertDominionInvariants`。预留是库存的子集，交付进入目标站库存；`mission.delivered` 是审计投影，不能在守恒总额里再加一次。耗能必须进入 `ledger.consumed`。
3. **旧Worker结果、旧导入或旧模型提案为什么不能覆盖新世界？** 看[页面](../../apps/portfolio/src/pages/StarCommand.vue)的 `compare`、`importJSON`、`reset`、`planMission` 与[Worker](../../apps/portfolio/src/workers/dominion.worker.ts)。Worker核对generation、sourceKey和当前快照；导入有importEpoch；规划有独立epoch及旧adapter的dispose，审批再次检查来源。
4. **策略比较为什么不把预测当成交付？** 看[比较器](../../packages/intelligence/src/dominion/comparison.ts)的 `compareStrategies`、[路径规划](../../packages/intelligence/src/dominion/planner.ts)的 `findPath`/`feasiblePath` 和页面 `adopt`。分支使用同一源快照；采用只提交将来的策略，不能导入分支终点。四种偏好都是明确成本下的启发式，不证明动态资源调度的全局最优。
5. **为什么导入JSON后不能直接相信其中的“成功”？** 看[记录验证](../../packages/intelligence/src/dominion/recording.ts)的 `validateRecording`/`replayFrame` 与[模型适配器](../../packages/intelligence/src/dominion/model-adapter.ts)的 `plan`/`approve`。记录需要隔离重演和完整事实一致；模型输出需要结构化合同、只读工具及人工批准。内部一致性不等于外部文件作者认证，替身通过也不等于真实模型验收。
