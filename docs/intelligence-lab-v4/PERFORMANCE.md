复现：先将干净V3生产包保存在忽略目录 `.local/v4/baseline/production-dist`，为当前干净源码执行 `npm run build`，再运行 `node scripts/measure-dominion.mjs`。脚本在本机两个独立端口顺序测量V3/V4，不同时运行两个浏览器负载；读取并核对开始/结束构建元数据，拒绝dirty源码。

固定条件为1440×900和390×844、DPR1、每版每尺寸3次、关闭缓存、至少100次实际绘制预热、10秒实际任务执行。V3手机默认限制30Hz；V4默认平衡档，按连续慢帧逐级降低画质并可退回二维，不能因视口宽度将硬件性能当成已知。两版任务规模及画布尺寸不同，所以只报告相同主机与采样方法下的实际默认体验，不声称等负载性能提升。

报告分别记录可操作控件出现时间、首次观察到场景绘制时间、冷加载资源传输/解码字节、实际画布像素、页面rAF与实际绘制计数的P50/P95、长任务、draw calls、几何/纹理数量及画质变化。冷加载在首次场景绘制截断；预热和活动期间另记，不能把全程数据标成首屏指标。localhost不压缩，不能代替公网延迟；上述可操作时间是观测代理值，不冒充Lighthouse TTI。

## 资源生命周期与边界

同一3c生产包的最终127/127浏览器批次，旗舰进出、体验镜头、换场景、导入返回实时、重置五类各10轮均通过。原始公开计数见[lifecycle.json](lifecycle.json)，`complete=true`；摄像往返还打开/关闭惰性资源标签，每轮保留源记录严格相等断言。它与上方12样本性能测量独立进行，没有同时运行其他捕获浏览器。

探针透明包装原生Worker、rAF、document/window监听器与WebGL创建/删除调用，记录geometry/material/texture/render-target相关底层buffer/program/texture/framebuffer创建释放与renderer计数，区分显式删除和上下文释放。应用及未知来源监听零增长；只有同时匹配安装版Playwright回调体和注册栈的监听单列，原始总数仍在记录中。历史357→373个活动buffer的失败已通过新session资源工厂与实例资源销毁修复，未提高阈值。

本报告不测量JavaScript堆GC或物理显存，也不代表长时间全天负载、手机真机、VR/XR、Internet延迟、Lighthouse或高画质所有相机的性能保证。近景射线构图只在对象/工作动作/相机改变时计算，不逐帧搜索；实际生产镜头和资源失败恢复由浏览器验收另证。减弱动效/二维仍保留业务语义，图形资源与任务状态分离。
