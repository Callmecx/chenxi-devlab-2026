记录日期：2026-10-13。当前结论：第六轮是 G1 预览视觉候选，已由实现者与集成负责人实际看图；不等于完整生产、性能或线上验收完成。

## 检查来源

开发截图来自本机 `http://127.0.0.1:5184/#/intelligence/preview-v4`，Chrome 实际渲染，1440×900 与 390×844、DPR 1。最新开发候选位于 `.local/v4/g1/r6/`，`observations.json` 记录相机、canvas 身份、渲染次数、业务时钟、视口与浏览器错误。第六轮的两种宽度各六个镜头共 12 张，未记录 console/pageerror，页面横向宽度未超过视口。

开发服务器可能发生 HMR，不能据此给最终成品签收。早期第 1、3 轮中标为 planet 的桌面文件在等待时发生重置、实际返回 overview；这些原文件保留为失败/无效样本。第 4 轮起脚本在等待后再次确认相机及 canvas 身份，不再把文件名当作状态证据。

## 已实际发生的迭代

| 轮次 | 从真实截图发现的问题                                                   | 实际修改与保留边界                                                                   |
| ---- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| R1   | 所有站点压进同一远景，主体像小型阵列；桥窗被结构挡住，控制台顶面难辨认 | 改为近景环港与前景舰的独立构图；保留失败截图                                         |
| R2   | 环站增大，但前方运输舰被下缘裁断；天体镜头缺少可操作站点               | 调整观察点、俯角及视线目标，天体模式同时包含所选区域真实站点                         |
| R3   | 前景船与泊位有尺度；观察桥外壳像大方盒，手机环港侵入标题；桥仅有装饰线 | 缩小桥外壳、分区窗面；手机单独拉开视角、移动构图；开始接真实仪表                     |
| R4   | 真实仪表已生成，但侧面贴图被斜台顶面遮挡；朝港镜头被旧塔楼挡住         | 将显示面抬至实体台面之上；继续实拍校验，不宣称贴图创建即显示正确                     |
| R5   | 仪表可见，但把观察桥抬高朝港后，窗外主要为空黑                         | 保留失败样本，恢复朝实际中远站点与航道的视线                                         |
| R6   | 桌面前景舰、环港、远景层次和桥内真实仪表可辨认                         | 接受为预览候选；手机侧面仪表仍自然裁边，不能称三屏均完整可读；不增加未经验证的重特效 |

三种舰体使用不同形体而非只改颜色。运输舰空舱、真实装载、在途推进、扫描和维修分别投影运行时事实；静态镜头截图不证明业务成功。指挥桥控制台显示同一世界的地图、能量、载荷、航段、任务状态和时钟，未使用伪随机遥测。

## 生产证据准备

可复现脚本：`scripts/capture-dominion.mjs`。它通过公开页面按钮和导出 JSON 读取真实状态，不向运行时注入成功结果、不修改 CSS 隐藏问题，也不剪接录像。

```powershell
$env:TEMP = 'D:\找工作创建个人项目集\chenxi-devlab-2026\.local\tmp'
$env:TMP = $env:TEMP
node scripts/capture-dominion.mjs http://127.0.0.1:4173/#/intelligence .local/v4/final-capture
```

脚本等待集成负责人给出的稳定生产包后运行。正式采集默认拒绝 `sourceTreeDirty: true`；如明确做候选采集，可设置 `CAPTURE_ALLOW_DIRTY=1`，输出将标为候选。`EXPECTED_REVISION` 可锁定完整源码 SHA。前后读取 `build-meta.json`，版本、构建时间、basePath 或 dirty 状态变化即判失败。

| 输出          | 证据约束                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| S1 全域揭幕   | 实际初始世界，主体与入口同框                                                                           |
| S2 指挥桥     | 同世界实体内部、真实外部站点与三块状态仪表                                                             |
| S3 装载/靠港  | 正常单步到真实运输 `load` 动作，导出的 `elapsed > 0`，再选择该舰与镜头                                 |
| S4 勘测扫描   | 实际合格勘测舰正在执行 `scan`，不能用闲置舰的装饰圆圈代替                                              |
| S5 维修/救援  | 实际维修舰执行 `repair` / `rescue`，保存目标、动作和进度来源                                           |
| S6 双策略未来 | 两 Worker 分支均返回，真实暂停世界在比较前后保持相同；手机需要第二视口时另存原图，不拼图               |
| 导览原始 WebM | 新会话自动运行导览；采样阶段、身份与时钟，不用拍摄操作触发用户接管；完成后导出实际发现、维修与交付证据 |

生产结果尚未写入本节。脚本准备或开发镜头检查通过不等于生产捕获成功；运行后应补实际目录、SHA、构建元数据、截图/媒体哈希、实际结束阶段及失败记录。录制观察耗时不是编码时长；仅在 `ffprobe` 实际返回时报告编码时长。

## 明确边界

390px 是桌面浏览器视口模拟，不是手机真机或 VR 设备验收。画面表现为原创、压缩尺度的程序化工业科幻场景，不称电影级资产、外部设计认证或真实航天验证。本文件不替代业务 E2E、资源释放、性能、无障碍或线上匿名检查的独立结果。
