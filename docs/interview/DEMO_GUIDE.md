## 三个 Why

**为什么把领域引擎与 3D 分开？** 业务成功必须来自约束满足和执行状态。把任务完成绑定动画会让暂停、降帧、重挂载或 WebGL 失败改变业务结果。这里引擎返回快照，三维与二维都读取同一份状态；二维降级保留操作。入口是 `createRuntime` 与 `IntelligenceScene.vue` 的状态投影。

**为什么请求失败后不直接换一个键重试？** 失败可能只发生在响应传输，服务已经提交。重试新键会把一个意图变成两个订单。客户端在发送前保存原键、原内容和恢复身份；unknown 时不允许清掉服务证据。查询暂未找到也不是“肯定没写入”。身份丢失时拒绝创建新身份重放旧请求，明确放弃需先归档。

**为什么回放要重新按前缀计算，而不是裁掉图表后半段？** 用完整序列先算 K 线会将未来最高价、成交量或闭合状态带入过去。金融样例每次只投影当前连续前缀，缺口阻断后续应用；恢复后重算。当前规模小，优先选择容易验证的纯函数；没有宣称实现大规模检查点系统。

## 两个真实失败及修复经过

这两项来自本轮开发和审阅，可以作为“怎样调试”的回答；不把已修复问题隐藏成从未失败。

1. **浏览器请求没有真正发出去。** 最初 API 客户端把原生 `fetch` 保存为实例方法，Chrome 抛出 `Illegal invocation`。Node 中注入的 mock transport 没暴露这个绑定问题。改为调用全局 `fetch` 的闭包后，重新跑真实 Chrome 的竞态与订单流程；服务不可用仍保留失败，不伪造成功。这说明单元测试不能替代实际浏览器链路。
2. **恢复请求存在，恢复身份却丢失。** 审阅发现旧 pending 留着而 token 丢失时可能建立新会话；unknown 时 reset 也可能清除服务证据。补充身份门禁、unknown 禁止重置和明确放弃前的有界归档。单元测试检查禁止 transport 调用；浏览器移除令牌并刷新后，验证零新会话、原键仍在，只有明确归档放弃后才建立新会话。没有将旧请求自动迁移到新身份。

## 被追问时的准确回答

- **“是不是自主 Agent / AGI？”** 不是当前完成声明；这里是确定性规则、可控工具、审批与回放的工程演示。真实模型执行接口模式未配置。旧 AI Agent Workbench 的真实 SSE 也不代表真实模型回答。
- **“是否已经上线后端或小程序？”** V2 静态作品已发布并通过匿名线上复验；真实 SQLite API 目前仅本机。小程序/App 资源编译不等于微信上线、签名 APK/IPA 或真机验收。
- **“测试全通过吗？”** 当前本机生产资源聚合为 64/64，单元/API 为 247/247，按本轮命令和版本回答。它们不包含真实模型、设备或公网验收；旧项目历史数量和450项功能评测、350个HTTP请求不合并成一个测试总数。见[生产浏览器记录](../testing/playwright-results.json)。
- **“性能提升多少？”** 展示已归档的 18 次导航测量、6 组独立 3D 空闲样本及 350 次本机 HTTP 样本，分别说明测量条件。首页手机模拟中位数为 89，未达到 90 分目标；3D 帧间隔不等于手机 GPU 性能。没有同条件基线对照，不提供提升百分比。
