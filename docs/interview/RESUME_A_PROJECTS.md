## 可直接替换：Chenxi DevLab V2 / Vue 与跨端全栈作品

**项目性质：**个人工程作品，AI 协同开发。**技术栈：**Vue 3、TypeScript、Vite、Pinia、uni-app、Fastify、SQLite、Vitest、Playwright。

- 构建个人作品主站、巷集 Select 模拟商城与蓉城周末 Lab 活动 H5，将页面、共享类型、领域规则和演示服务分层；保留公开静态本地模式与显式服务模式，避免接口失败被本地假成功掩盖。
- 在商城服务中以整数分计算金额，结合购物车版本、有效期报价、库存预留和优惠状态维护下单约束；活动流程实现偏好解释、场次校验、一次有效预约及取消释放名额。
- 通过 SQLite 事务与会话隔离实现持久化演示数据；发送前保留幂等键和原请求体，提供结果未知、操作查询与原键重试，并阻止恢复身份丢失后的跨会话重放。
- 编写领域/客户端/服务测试与浏览器业务用例，实际验证响应丢失、重复操作、库存竞争、会话边界及 390px/1440px 交互；构建产物、真机验证和公开发布分别记录。

**边界可放在项目末尾：**数据与付款均为模拟；真实 API 当前仅本机运行，公网为静态演示。微信小程序和 App 资源编译不等于商店上线或设备验收。最终 V2 聚合与发布结果以验收报告为准。

源码仓库：[Callmecx/chenxi-devlab-2026](https://github.com/Callmecx/chenxi-devlab-2026)。V2 文件在最终发布前以当前工作树为准，不能假定远端 `main` 已包含全部内容。

## 可直接替换：EnterpriseFlow / 企业业务模拟系统

**项目性质：**个人业务模拟，AI 辅助开发。**技术栈：**Vue 3、TypeScript、Java 21、Spring Boot、MyBatis、MySQL、Redis。

- 围绕销售、采购、仓库与财务协同，梳理角色权限、销售审批、库存预留、缺口采购、到货出库与分次结算的业务闭环，业务账号及交易数据均为模拟。
- 针对现货不足场景保留部分预留与采购缺口关系，通过事务和幂等处理重复审批/收货；使用 BigDecimal 与服务端校验维护金额、权限和剩余应收约束。
- 整理可核对的业务验收与七角色流程证据；区分历史回归、库存正确性场景和生产性能验证，不将有限并发用例描述为生产吞吐保证。

**历史依据：**原 README 记录 19/19 业务回归、七角色链与重启持久化；本轮没有重新运行原服务，历史验收日期未独立确认。单仓、全量收货出库，无生产多租户、完整财务总账或真实支付声明。

公开源码：[Callmecx/enterprise-flow](https://github.com/Callmecx/enterprise-flow)。本轮 DevLab 中的 50/30/20 浏览器流程是独立仿真，不充当原 Java 项目的新验收。

## 可选补充：前端工程交互实验

适合强调复杂交互、状态与性能方法的岗位；属于 DevLab 子模块，不重复计为新公司或独立商业项目。

- 实现合成金融事件的播放、暂停、seek、缺口回补和重复去重，按连续前缀重算报价、订单簿与 K 线，验证未来事件变化不会污染当前历史状态。
- 将十万条合成记录的筛选排序置于 Web Worker，以代次和 terminate 隔离过期任务；使用可视窗口限制 DOM，记录当前机器实际计算/传输时间，而非预设性能成绩。
- 提供可操作的库存竞态和订单故障实验，展示服务终态、unknown 恢复、非法流程拒绝与可追溯记录。
